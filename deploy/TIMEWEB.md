# Переезд med-local.ru с Vercel на Timeweb App Platform

Файл служебный (`deploy/` в `.vercelignore`, на сайт не попадает).
Порядок: **этап 1** (временный домен, DNS не трогаем) → проверка → **этап 2** (DNS только по команде «переключай», ночью по Москве). Vercel остаётся включённым 2 недели.

## Схема выкладки

В панели у приложения нет поля «команда сборки», поэтому собирает GitHub Actions (`.github/workflows/deploy-dist.yml`). На каждый пуш в `main` (и, пока идёт переезд, в `infra/timeweb-migration`):

1. `check-site.js` (с ошибками дальше не идём) и `build-dist.js` (сайт без служебных файлов);
2. в `dist/version.txt` записывается SHA коммита;
3. содержимое публикуется force-пушем в две служебные ветки:
   - **`timeweb-dist`**: только содержимое `dist` (для приложения «Статический сайт», директория `/`);
   - **`timeweb-docker`**: `Dockerfile` + `Caddyfile` + `site/` (для приложения типа Dockerfile);
4. workflow опрашивает `/version.txt` на Timeweb до 10 минут и в логе пишет «Выложено» или ошибку (статус виден в GitHub → Actions).

Адреса для шага 4: **Settings → Secrets and variables → Actions → Variables**: `DEPLOY_CHECK_URL` (static-приложение), `DEPLOY_CHECK_URL_DOCKER` (Docker-приложение). Пустая переменная — шаг пропускается.

Ветки `timeweb-dist` и `timeweb-docker` перезаписываются целиком: руками в них ничего не править.

## Какой вариант приложения выбрать

По документации Timeweb ([Настройки веб-сервера](https://timeweb.cloud/docs/apps/reverse-proxy)) в панели **нет конфигурационного файла**, а есть формы:

| Что | Возможности панели | Нужно сайту |
|---|---|---|
| Редиректы | до 10 штук, точный путь (`/старый` → `/новый`), коды 301/302/307/308, подстановки и регулярные выражения не упоминаются | 301 на `multipleksny-proryv` (хватает), **cleanUrls и `/x/` → `/x` (не хватает)** |
| Заголовки | до 10 правил на всё приложение (set/add/delete), по путям не задаются | `X-Robots-Tag` только для `/blog/_cards/*` и разный кэш для HTML и картинок задать **нельзя** |
| Сжатие | gzip и zstd | подходит |
| Несуществующие пути (только «Статический сайт») | SPA-fallback вкл/выкл; если выкл. и в сборке есть `/404.html`, отдаётся он; без него пустая 404 | подходит (в dist есть `404.html`) |

Что показал замер временного адреса (приложение со ссылкой на `main`, до этой работы): `/about` отвечает 308 на `/about/` (так работает файловый сервер), `/blog/_cards/1` возвращает главную с кодом 200 (файла нет, включён SPA-fallback), поэтому **кнопка «Показать ещё» в блоге на статическом варианте без cleanUrls не работает**. Каноникалы сайта без слэша (`/about`), поэтому вместо них отдавался бы редирект на `/about/`.

**Вывод:**
- **Вариант Docker (рекомендуется, `timeweb-docker`)**: полный Caddyfile: cleanUrls, все редиректы, заголовки по путям, кэш, настоящий 404 с `404.html`. Это единственный вариант, который повторяет Vercel.
- **Вариант «Статический сайт» (`timeweb-dist`)**: допустим только как временный. Не работают cleanUrls и «Показать ещё» в блоге, `X-Robots-Tag` для `/blog/_cards/*`. Переключать на него боевой домен нельзя, пока не решены эти пункты.

Если в вашем диалоге «Настройки веб-сервера» на самом деле есть текстовое поле для конфига (в документации его нет), пришлите скриншот: тогда `deploy/Caddyfile` можно вставить в него.

## Этап 1. Временный домен

### 1А. Docker-приложение (рекомендуется)
1. App Platform → **Создать приложение** → тип **Dockerfile**, репозиторий `gmtossoriamkt/med-local`, **ветка `timeweb-docker`**, поле «Путь к директории проекта» пустое (Dockerfile в корне ветки), «Сборка по последнему коммиту» включена. Порт 80 задаётся в Dockerfile (`EXPOSE 80`).
2. Дождаться деплоя, записать временный адрес.
3. В репозитории (GitHub) создать переменную `DEPLOY_CHECK_URL_DOCKER` с этим адресом.

Ветки `timeweb-docker` ещё нет: она появится после первого запуска workflow (то есть после пуша ветки `infra/timeweb-migration`). Для проверки до слияния в `main` workflow срабатывает и на ней.

### 1Б. Статическое приложение (текущее)
1. **Ветка: `timeweb-dist`**, директория сборки `/`, путь проекта пустой. Команды сборки нет, не нужна.
2. **Настройки веб-сервера → Настроить:**
   - Редирект: тип *path*, источник `/blog/multipleksny-proryv`, назначение `/blog/pcr-panely-pp1875-vtoroy-lishniy`, код 301.
   - Заголовки: *set* `X-Content-Type-Options` = `nosniff`; *set* `Referrer-Policy` = `strict-origin-when-cross-origin`.
   - Сжатие: gzip и zstd.
   - Несуществующие пути: **SPA-fallback выключить** (тогда отдаётся `404.html` со статусом 404).
3. Создать переменную `DEPLOY_CHECK_URL` = `https://gmtossoriamkt-med-local-a033.twc1.net`.

### 1В. Проверка
```bash
node scripts/check-live.js --base https://<временный-адрес>
```
Проверяются: все 87 страниц sitemap, редиректы, настоящий 404, картинки/WebP, видео (Range → 206), служебные файлы не отдаются, кэш и `X-Robots-Tag`, сжатие. DNS не меняется.

## Этап 2. Переключение DNS (только после «переключай»)

### За 1–2 дня
1. В DNS-зоне снизить TTL `A` (корень) и `www` до **300 с**. Значения (`216.198.79.1`) не менять.
2. Приложение остаётся на служебной ветке (`timeweb-docker`): она обновляется на каждый пуш в `main`, поэтому новые статьи попадают на оба хостинга. Сменить ветку приложения не нужно: `timeweb-dist` и `timeweb-docker` принимают выкладку только из workflow.
3. Добавить домены `med-local.ru` и `www.med-local.ru` в приложение (**Домены → Привязать**); сертификат выпустит Timeweb после того, как DNS укажет на него.

### В ночь переключения (02:00–05:00 МСК)
1. Записать текущие значения `A` и `www`.
2. Заменить `A med-local.ru` на IP приложения; `www` на CNAME на адрес приложения или тот же IP.
3. Через 5–15 минут: `node scripts/check-live.js --base https://med-local.ru`. Если сертификата ещё нет, подождать до 15 минут.
4. Через 1–2 дня проверить в Яндекс.Вебмастере и Search Console обход.

### Откат (5–15 минут при TTL 300 с)
Вернуть `A med-local.ru = 216.198.79.1` и прежнее значение `www`. Vercel деплоит `main` и остаётся рабочим 2 недели.

### Через 2 недели
Поднять TTL обратно, отключить Vercel (только по отдельному решению).

## Известные риски
- **Сейчас приложение со ссылкой на `main` отдаёт служебные файлы** (`CLAUDE.md`, `README.md`, `scripts/*.js`, `vercel.json`, `.githooks/*`, `drafts/`): `.vercelignore` на Timeweb не действует. Переключить приложение на `timeweb-dist` или `timeweb-docker` надо до привязки боевого домена, лучше сразу.
- Нет brotli (только gzip/zstd): размер HTML по сети будет немного больше.
- Автодеплой Timeweb без внятного статуса: статус «выложено» берём из workflow (`version.txt`) и лога деплоя в панели.
- Регулярные выражения и подстановки в редиректах панели не поддерживаются (поэтому для cleanUrls нужен Docker).
