# Переезд med-local.ru с Vercel на Timeweb App Platform

Файл служебный (в `.vercelignore`, на сайт не попадает). Названия кнопок в панели Timeweb могут отличаться от описанных: ориентируйтесь на смысл.
Порядок: **этап 1** (временный домен, DNS не трогаем) → проверка → **этап 2** (переключение DNS только по команде «переключай», ночью по Москве). Vercel остаётся включённым 2 недели.

## Что уже подготовлено в репозитории (ветка `infra/timeweb-migration`)

| Файл | Зачем |
|---|---|
| `scripts/build-dist.js` | собирает папку `dist` без служебных файлов (`scripts/`, `drafts/`, `.githooks/`, `CLAUDE.md`, `README.md`, `vercel.json`, `.github/`, `deploy/`) |
| `404.html` | страница 404 в стиле сайта (noindex) |
| `deploy/Caddyfile` | редиректы, cleanUrls, заголовки, кэш, настоящий 404 (копия `vercel.json`) |
| `deploy/Dockerfile` | вариант приложения с собственным Caddy (если в панели нельзя править веб-сервер) |
| `scripts/check-live.js` | проверка развёрнутого сайта по адресу |
| `.github/workflows/checks.yml` | на каждый пуш: `check-site.js` + `build-dist.js` (выкладки нет) |

## Этап 1. Приложение на временном домене

### 1.1. Создать приложение
1. Панель Timeweb Cloud → **Apps** (App Platform) → **Создать приложение**.
2. Тип: **Frontend → Static / Статический сайт** (как у Probarium). Подключить GitHub-репозиторий `gmtossoriamkt/med-local`, ветка для проверки: **`infra/timeweb-migration`** (потом поменять на `main`).
3. **Команда сборки:** `node scripts/build-dist.js`. **Папка публикации:** `dist`. Версия Node: 20 или 22 (скрипт не требует пакетов, `npm install` не нужен).
4. Тариф: места нужно не меньше 100 МБ (сайт ≈ 32 МБ вместе с видео 24 МБ).
5. Запустить деплой. Записать временный адрес приложения (вида `….twc1.net`) и IP.

### 1.2. Настроить веб-сервер (редиректы и настоящий 404). Выбрать один вариант по тому, что доступно в панели

**Вариант А — «Настройки веб-сервера / Caddy» доступны.** Вставить содержимое `deploy/Caddyfile`. Поменять `root * /srv` на корень, который указан в панели (если он другой). Сохранить, перезапустить деплой.

**Вариант Б — доступна только галочка SPA / «все запросы на index.html».** Отключить её: тогда несуществующие адреса перестанут отдавать 200. Но:
- страницу `404.html` сервер может не использовать (останется стандартный ответ 404, это допустимо);
- **редиректы и cleanUrls не заработают:** `/about` будет перенаправляться на `/about/` (каноническим остаётся `/about`) и 301 для `/blog/multipleksny-proryv` не будет. Это ухудшает SEO. Для боевого переключения такой вариант не рекомендую.

**Вариант В (рекомендуется, если А недоступен) — Docker-приложение.** Создать приложение типа **Docker** из того же репозитория, Dockerfile: `deploy/Dockerfile`, порт 80. Caddy внутри образа берёт `deploy/Caddyfile`, сборка `dist` идёт в образе. Автодеплой по пушу работает так же.

Если не получается ни А, ни В — написать в поддержку Timeweb: «нужен возврат HTTP 404 для несуществующих путей статического приложения с отдачей /404.html и возможность задать редиректы 301/308 и заголовки (Cache-Control, X-Robots-Tag)».

### 1.3. Проверка (делаю я, когда пришлёте временный адрес)
```bash
node scripts/check-live.js --base https://<временный-адрес>
node scripts/check-site.js
```
Проверяется: все 87 страниц из `sitemap.xml` (код 200, тип HTML), редиректы (`/about/`, `/about.html`, `/index.html`, 301 для `multipleksny-proryv`), настоящий 404, картинки и WebP, видео с `Range` (206), `robots.txt`, `sitemap.xml`, кэш-заголовки, `X-Robots-Tag` на `/blog/_cards/*`, отсутствие служебных файлов, сжатый вес страниц. Результат пришлю отчётом; DNS не меняется.

Что смотреть глазами в браузере: главная, блог («Показать ещё»), видео по клику, статья с таблицей, форма/кнопки Telegram и MAX, 404.

## Этап 2. Переключение DNS (только после «переключай»)

### За 1–2 дня до переключения
1. В DNS-зоне `med-local.ru` (где она сейчас, у Timeweb или у регистратора) снизить TTL записей `A` (корень) и `www` до **300 секунд**. Сами значения (`216.198.79.1`) не менять.
2. **Приложение остаётся на ветке `infra/timeweb-migration` до конца переезда.** После переключения DNS и успешной проверки (и только по отдельному решению) ветку `infra/timeweb-migration` сливаем в `main` (пуш в `main` только по слову «пуш»), затем в приложении: **Настройки → Репозиторий → Ветка** меняем на `main` и перезапускаем деплой. Сразу после смены ветки: `node scripts/check-live.js --base https://med-local.ru` и проверка `Last-Modified` главной.
   Пока приложение на ветке переезда, новые статьи в `main` на Timeweb не попадают: публикуем их и в ветку (или сливаем `main` в `infra/timeweb-migration`), либо делаем смену ветки раньше.
3. Добавить в приложении домены `med-local.ru` и `www.med-local.ru` (**Домены → Привязать домен**). Сертификат (Let's Encrypt) Timeweb выпустит после того, как DNS укажет на приложение.

### В ночь переключения (после «переключай», 02:00–05:00 МСК)
1. Записать текущие значения: `A med-local.ru = 216.198.79.1`, `www` = как сейчас (CNAME/ALIAS).
2. Заменить `A med-local.ru` на IP приложения Timeweb (панель покажет). `www` — на CNAME на адрес приложения или на тот же IP.
3. Подождать 5–15 минут, проверить:
   ```bash
   node scripts/check-live.js --base https://med-local.ru
   ```
   Если сертификат ещё не выпущен, подождать до 10–15 минут: браузер на это время покажет предупреждение.
4. Сообщить результат. Яндекс.Вебмастер и Search Console: проверить, что обход идёт (через 1–2 дня).

### Откат (5–15 минут при TTL 300 с)
Вернуть `A med-local.ru = 216.198.79.1` и прежнее значение `www`. Vercel продолжает деплоить `main` и остаётся рабочим 2 недели.

### Через 2 недели
Если проблем нет: поднять TTL обратно (3600), отключить Vercel (проект и домен). Только по вашему отдельному решению.

## Известные риски
- Мягкий 404 (см. `probarium/.local/hosting-404.md`): проверяется `check-live.js`.
- Нет brotli (только gzip/zstd): размер HTML по сети будет другим (обычно +5–10 %).
- Превью веток нет: проверять через временный домен.
- Автодеплой Timeweb без внятного статуса ошибок: смотреть лог деплоя в панели и `Last-Modified` главной.
